# Offline receipt-bound historical owner issuance

2026-10-26. Local successor to the [raw13C registry receipt](folderfollow-reveal-registry-receipt.md),
composed with the [checked44-byte owner kernel](folderfollow-reveal-paint-retirement.md).
This is not an ELF/firmware builder, installed hook, native lifetime lease,
producer-generation transport, release certificate or cleanup authorization.
No image/device/UI/network/commit/push action is performed by this step.

## One current invocation, not a latest-pointer lookup

The receipt emitter now has an explicit optional publication_callback. Its
defaultNone preserves all prior2,196 bytes and labels. Only after fresh captured
raw13C=0, route checks, complete receipt-prefix/schema validation, capacity and
all-zero target validation does it call the generated issuer. The36-byte owned
stack request contains this invocation's controller, pinned13C mutex, native
node/engine scalars, native frame/caller, publication site, raw status and next
receipt sequence. It is not a pointer to a mutable/latest journal record.

The issuer copies that request into its own frame, validates route/extents and
its separate binding table, then calls the actual checked open_owner entry.
No direct owner-state read occurs in the issuer. The same engine scalar in two
native registrations produces distinct owner tickets; neither equal engine,
name, node nor a constructor's outer return substitutes for a captured ticket.
No new producer API, latest-owner lookup or implicit registration-on-refusal
is exposed. Native producer43C860 still lacks an independently admitted owner
argument; native object layouts have no verified spare generation field, and
the three native stack-carrier words expire on return.

## Checked distinct mutexes and bounded nesting

The new composition pins both24-byte mutex allocations and rejects equal or
partly overlapping extents. Registry13C remains genuinely held from the fresh
receipt while the owner kernel acquires paint148: this introduces13C->148.
Existing source contracts show no reverse nested edge in the four examined
paint append/get/remove/destroy bodies, and teardown releases148 before its
later13C acquisition. This is bounded local evidence, not whole-program
deadlock freedom or permission to hold arbitrary native locks across callbacks.

The44-byte assembler's new optional expected_mutex_address is allowed only in
checked mode. The actual U+148 snapshot must match the pin BEFORE raw acquire;
it cannot silently become13C and attempt self-locking. Omitting this pin keeps
both earlier44-byte variants byte-identical (default10,824/checked12,120 bytes).
The pin is only a scalar binding, not initialized/retained mutex evidence.

Successful issuance performs raw148 acquire, private scalar owner-schema/mint
work, and raw148 release. It invokes no list method, engine/name load, native
free, destructor, renderer or UI action. All binding-table reads/writes use the
still-held outer13C guard; actual owner-state accesses use148. The composer
validates complete generated code and data extents against each other, both
mutexes/controller and pinned native RX, not merely a callback entry address.
Resolved imports, genuine ordinary mutex behavior, stable controller fields,
retained native allocations and separately mapped private storage remain
premises. Bounds cannot establish unused native data/GOT or heap lifetime.

## Immutable historical binding and narrow quarantine

The separate16-byte binding header stores count, quarantine, exact raw error
status and reserved zero. Each48-byte row stores OWNR magic, dense binding
sequence, issued owner ticket, controller, registry mutex, node, engine, native
frame/caller, publication site, raw13C status0 and receipt sequence. Owner
tickets are positive and strictly increasing but NOT dense: publication nonces
share their serial. Receipt sequences can likewise have gaps in this table.
Old node/engine/frame/caller words are historical scalars and are not followed.

Binding header/prefix, free capacity and all-zero target slot are checked before
open_owner. Rolled-back count, skipped/corrupt prefix or dirty target cannot
reuse an issued binding; schema faults quarantine only this table under13C.
Valid full capacity denies without minting an unrecordable owner. A replayed/
reordered receipt does not mint again. The copied request survives the hostile
raw ABI and is not reread from its caller after the nested operation. Body and
magic publication precede count publication with barriers; neither table is
reset/recycled while a captured identity remains visible.

Only owner>0 with raw status0 can publish a binding. A raw148 acquisition or
release error saves its exact32-bit status and latches this issuance table's
quarantine while13C is still held. No positive binding is published. The issuer
does not read back, retire, close, repair, retry or guess an unlock of owner
state. An unlock error may have already minted an owner row; a nonzero acquire
may still own a robust/unknown mutex. There is no rollback promise.

This quarantine suppresses later issuer callbacks only. It does NOT stop direct
44-byte publish/claim/retire operations using previously captured tickets.
Full-instance external quarantine and complete cooperative producer coverage
remain unimplemented integration gates. Existing outer13C unlock still hides
raw status: a stored binding is an acquisition/issuance history, NOT successful
release or a native lifetime/free certificate. The passive receipt may still
be recorded when owner issuance is denied; they are distinct observations.

## Preserved behavior and new costs are different claims

The original native registration instructions, resulting links, final registers
and HI/LO are preserved in the local fixture. Native allocation failure still
bypasses13C unlock; raw13C failure still permits the original unchecked writes.
The observer does not repair those native defects. New nested locks and scalar
work DO change stack depth, scheduling, blocking and timing; architectural
result comparisons do not establish progress/equivalence on hardware.

There are192 bytes for the receipt observer,192 for issuer and160 for the
owner kernel:544 bytes of simultaneously nested helper frames, plus native
registration, imports/library stack and other callers. Per-frame checks do not
prove this aggregate safe. The global466DA0 bridges still add192 bytes even to
unrelated calls. Four coherent redirects remain mandatory; the previously
documented partial-installation counterexample is not repaired or supported.

The in-memory composer produces only bytes/labels, no image or installation.
Complete creation/user/lifecycle coverage, retained engine/controller ownership,
generation transport, checked cleanup continuations, UI transaction and active
folder-follow remain gated. Raw13C source is the unchanged02fd reference,
SHA-256`02fd1dd13db7aac1e6d150ec1866b93f57022c1d668b114720a36b7f232e5f87`.
